## **2.1 UI/UXコンポーネント配置とプロアクティブ通知方針**

LINE公式アカウントのトーク画面は、下部に固定表示される「リッチメニュー」と、動的コンテンツを表示する「Flex Message」および「クイックリプライ」を活用し、操作摩擦を最小化する。

### **リッチメニュー配置仕様**

| エリア領域 | ボタン名称 | アクションタイプ | 発動処理・システム挙動 |
| :---- | :---- | :---- | :---- |
| **左上（大型）** | **【緊急】タスク開始** | ポストバック (action=start) | 現在時刻を刻印し、50分タイマー等のカウントダウンを開始。AIが監視フェーズへ移行。 |
| **右上（大型）** | **【完了】実績報告** | ポストバック (action=complete) | 成果物（画像・テキスト・音声等）の提出プロンプトを起動。 |
| **左下（中型）** | **予定変更・SOS** | ポストバック (action=sos) | 単発2分岐問合せ（①恐怖/心理的抵抗 vs ②物理的制約）を即時発射。①は議論ゼロで10分・1行行動へ縮小着手、②は延期処理の上、夜間分析で逃避パターンを炙り出す。 |
| **右下（中型）** | **ステータス/規律スコア** | メッセージ (ステータス確認) | 連続達成日数、ペナルティ保留額、規律評価スコア（0-100）を表示。 |

### **プロアクティブ通知方針（追いLINE無しの原則）**

ユーザーの利便性と心理的負担に配慮し、**定刻の単発通知のみ**を実施する。
- ユーザーから返信・応答がない場合でも**追撃通知（追いLINE）の連投は行わない**。
- 無応答時はサイレントで規律スコアの減点や状態ログ記録を行い、次の定刻チェックインまたは夜間22:00の1日総括査定にて一括判定・ペナルティ処理へ移行する。

## **2.2 ユーザー状態遷移モデル (FSM)**

対話エンジンは有限状態機械（Finite State Machine: FSM）として管理され、状態ごとにAIの応答ロジックおよびペナルティ発生判定が自動制御される。

| 状態（State） | トリガーイベント | ユーザー期待行動 | 制限時間 / 閾値 | 逸脱時の自動処理（自動介入） |
| :---- | :---- | :---- | :---- | :---- |
| **1. IDLE / PENDING** | 朝の定刻（07:00）の自動Push送信 | 当日の行動計画（タスク、50分単位の開始時間、成果物定義）を送信 | 朝の指定時間内 | 追いLINEは送らず、サイレントで規律スコア減点・ログ記録。 |
| **2. SCHEDULED** | 行動開始予定時刻の到達 | リッチメニュー「タスク開始」のタップ | 予定時刻 | 1回のみ開始確認通知を送信。無応答でも追いLINEは送らず、夜間一括査定対象に登録。 |
| **3. EXECUTING** | タスク開始ボタンのタップ | 定められた作業（基本50分ブロック）の遂行 | 予定作業時間（例: 50分） | 作業中の生存確認・追いLINEは行わない。離脱申し出時のみ即時判定。 |
| **4. REPORTING** | 作業終了タイマー満了 | 成果物（証拠写真、音声、テキストログ）の送信 | タイマー終了後 | 追撃催促はせず、未提出のまま経過した場合は夜間査定で不備・ペナルティ確定。 |
| **5. ESCAPED** | 応答拒否、未提出、時間切れ | 弁明およびリカバリー計画の提示 | 夜間総括時 | 事前に設定したアンチチャリティ寄付の仮決済、指定SNSへの自動曝露。 |
